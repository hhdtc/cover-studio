# Apple 官网逆向：排版与动效

对三个公开页面做了一次**被动读取**。重点是排版与动效，但同时记录了版式、配色、材质与组件形态——一个只讲字体和动画的分析，解释不了页面为什么看起来是这样。

- 观察时间：2026-10-31
- 页面：`/`、`/ipad-pro/`、`/iphone-duo/`（三页均 200）
- 手段：REA `inspect_web_page` / `capture_web_screenshot`（CDP 被动观察）+ 读取页面声明的 16 个样式表（约 1.63 MB）+ 一次 1600×913 下的计算样式普查
- 产物：`src/apple-kit/`（8 个组件）、`src/views/AppleKitView.vue`（`#/apple-kit`）

> 站点内容（SF Pro 字体、产品图片、商标、文案）版权归 Apple Inc. 所有。这里只保留**数值规律**，不附带任何原始素材。

## 3. 字号梯级

计算样式里反复出现的字号（px）：

```
12 · 14 · 17 · 19 · 21 · 24 · 28 · 32 · 40 · 48 · 56 · 64
```

声明值频次最高的是 17px（63 次），其次 14px（55）、12px（48）。

关键不是数字本身，而是**三元组绑定**——每级字号都配着固定的字距与行高：

| 字号 | 字距 | 行高 | 角色 |
| --- | --- | --- | --- |
| 80px | -0.008em | 1.06 | 首屏大标题 |
| 56px | -0.005em | 1.12 | 章节标题 |
| 48px | -0.003em | 1.08 | 产品名 |
| 40px | -0.001em | 1.08 | 次级标题 |
| 28px | +0.007em | 1.14 | 卡片标题 |
| 24px | +0.009em | 1.17 | 小标题 |
| 21px | +0.011em | 1.38 | 导语 |
| 17px | -0.022em | 1.47 | 正文（基准） |
| 14px | -0.016em | 1.29 | 控件标签 |
| 12px | -0.010em | 1.34 | 说明与法务 |

规律：**越大的字越收紧，中等字号反而轻微放宽**（21–24px 取正值），行高从 1.06 一路开到 1.47 给正文留呼吸。

字重分布：600 出现 214 次，400 出现 127 次，500 仅 16 次。显示级统一 600，不用 700/800 造成压迫感。

## 4. 动效

### 时长刻度

样式表里 transition 时长的出现频次：

```
320ms ×63 · 400ms ×44 · 300ms ×38 · 240ms ×31 · 250ms ×20 · 500ms ×17 · 100ms ×15
```

主刻度是 **240 / 320 / 400 / 500ms**，100ms 只用于即时反馈。

### 驱动方式

`animation-timeline`、`scroll-timeline`、`view-timeline` 的出现次数**都是 0**。也就是说滚动效果不是 CSS 滚动时间线，而是脚本读取滚动位置后改写变换。`will-change` 在产品页高达 172 处，说明大量图层被提前提升到合成层。

### 关键帧家族

按命名可归为五类：

1. **导航飞入/飞出**（flyout slide forward/back、scrim 高度变化、search fade-and-slide）
2. **分页圆点**（dotnav shift / timed dot expand）
3. **颜色过渡**（`animate-color-*` / `animate-background-*`，时长 1s）
4. **缎带落下**（ribbon-drop）
5. **媒体旋转**（inline-media-spin）

颜色过渡单独成族这一点值得注意：他们把「区块换色」当成一等动画，而不是附带效果。

## 5. 材质：玻璃阶梯

第二轮专门量了毛玻璃。计算样式里带 `backdrop-filter` 的元素：iPad Pro 页 29 个、首页 2 个。按「模糊半径 / 底色透明度」可以归成三档：

| 档位 | 模糊 | 底色 | saturate | 尺寸 | 出现 |
| --- | --- | --- | --- | --- | --- |
| 全局导航 | 20px | `rgba(29,29,31,0.8)` | 180% | 44px 高、fixed | 每页 |
| 飞入蒙层 | 20px | `rgba(0,0,0,0.4)` | — | 满视口、fixed | 每页 |
| 悬浮药丸 | 7px | `rgba(66,66,69,0.7)` | — | 56px 高 | 20 处 |

两个值得抄的细节：

1. **特性检测回退**：样式表里有 `@supports (backdrop-filter: initial)`。不支持时退回不透明底，而不是留一块半透明色。
2. **模糊是过渡出来的**：蒙层的 `backdrop-filter` 在 `blur(0px)` 与 `blur(20px)` 之间有过渡值，不是开关。

另外 `prefers-reduced-transparency` 的出现次数是 **0** —— 他们没有为「降低透明度」这个偏好做降级，只在 `prefers-contrast` 上有一处处理。

**焦点环**：实测为双层 `box-shadow: 0 0 0 3px #fff, 0 0 0 5px #0071e3`，即白色 3px 间隙 + 蓝色 5px 外环，代替浏览器默认 outline。

## 6. 叙事结构

产品页的长文档不是平铺，而是两种结构的组合：

- **吸顶叙事**：图形列 `position: sticky` 固定，文案列滚动；只有进入视口中带的段落才点亮，其余保持低不透明度。sticky 的 `top` 必须减去全局导航高度。
- **横向吸附画廊**：`scroll-snap-type: x mandatory`，出现 3 次；媒体画廊与滚动容器都用 `x mandatory`。不需要手势库，滚轮与触控板自然吸附。

局部导航（Overview / Specs / Compare）是第二层吸顶条，`top` 等于全局导航高度，本身也带模糊。

## 7. 版式与节奏

样式表里的宽度和断点是非常集中的一套：

| 项 | 数值 | 出现次数 |
| --- | --- | --- |
| 容器宽度 | 734 / 833 / 1068 / 1023 / 1440px | 807 / 159 / 644 / 28 / 14 |
| 断点 | 734 / 1068 / 833 / 1023 / 480px | 717 / 565 / 157 / 26 / 21 |
| 布局方式 | flex 185 次 / grid 27 次 | — |
| 卡片圆角 | 18 / 28 / 32px | 22 / 38 / 30 |
| 药丸圆角 | 980px | 11（首页 35 处） |
| 小控件圆角 | 5 / 8 / 10px | 8 / 11 / 17 |

两个结构性观察：

1. **宽度是阶梯，不是断点的复制**：734 → 833 → 1068 三档，超过 1068 后由外边距接管，而不是继续加宽。
2. **纵向留白几乎都是不对称的**：实测到 40/84、76/76、90/0、44/57、62/10 这类组合。上紧下松会让区块看起来是「落」在页面里，而不是垂直居中放置。

flex 承担绝大多数排布，grid 只出现在确实需要二维对齐的地方（画廊、表单栅格）。

- 暗色：`#000` / `#161617` / `#1d1d1f` 三层底，正文 `#f5f5f7`（出现 402 次），次级 `#86868b`（97 次），链接 `#2997ff`（43 次）。**暗色页不用纯白正文**。

## 9. 响应式

同一页面（iPad Pro）在三个宽度下的实测对比：

| 宽度 | 导航可见链接 | 导航条高 | 纵向堆叠块 | 吸顶元素 | 隐藏元素 |
| --- | --- | --- | --- | --- | --- |
| 390px | 3（汉堡） | 48px | 113 | 31 | 337 |
| 834px | 14 | 44px | 66 | 31 | 310 |
| 1600px | 14 | 44px | 61 | 31 | 309 |

三点结论：

1. **塌陷集中在导航层**：834 以下导航换成汉堡、条高从 44 涨到 48；正文只是从两列变一列。
2. **吸顶是结构，不是桌面特效**：三种宽度下吸顶元素都是 31 个。
3. **图片按同一组断点换素材**：549 个 `<source>` 的 `media` 只有三种 —— `(max-width:734px)`、`(max-width:1068px)`、`(min-width:0px)`。

## 10. 媒体加载策略

这块和常识相反：

| 项 | 实测 |
| --- | --- |
| 视频总数 | 17 |
| `preload="none"` | 17 |
| `playsinline` | 17 |
| `poster` | 0 |
| `autoplay` 属性 | 0 |
| 初始 HTML 带 `src` | 2 |
| 图片 `loading="lazy"` | **0** |
| `<source srcset>` | 549 |
| `link rel=preload` | 0 |

结论：**原生懒加载一条没用**。视频靠 `data-inline-media-*` 一组属性（播放时机、退出复位、超时、retina 开关）由脚本调度；图片用 `<picture>` 的 549 个 `<source>` 做分辨率切换，再用 `onload` 控制揭示。

本库的 `ApLazyMedia` 用 IntersectionObserver 在距视口 240px 时注入 `src`，并在 `navigator.connection.saveData` 为真时退化成手动按钮。

## 12. 实现取舍

1. **滚动用 rAF 合并读取**：passive 监听，一帧只读一次布局，元素离屏时不调度工作。原站的做法类似，但我们的实现只依赖 CSS 变量，不直接在 JS 里写 transform 字符串。
2. **合成层优先**：位移统一 `translate3d`，不碰 `top/left`。
3. **颜色插值走 oklab**：`color-mix(in oklab, ...)` 比 sRGB 直插少一段发灰的中间态。
4. **可访问性**：`prefers-reduced-motion` 与 `.apl-no-motion` 双开关，都会把时长压到 1ms；控件保留 `focus-visible` 轮廓。
5. **前缀隔离**：类名 `apl-`、变量 `--apl-*`，与站内既有的 `ef-` / `efk-` 互不干扰。
